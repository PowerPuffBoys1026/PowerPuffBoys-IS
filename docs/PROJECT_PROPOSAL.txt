1. Executive Summary

1.1 Project Overview
ClassMate is a cross-platform academic companion application for students. It solves the problem every student faces daily: losing track of class schedules, accumulating absences without noticing, and missing assignment and exam deadlines. Instead of juggling scattered notes, group chats, and memory, ClassMate gives students one place to view their weekly timetable, mark their attendance with a single tap, monitor their absence percentage per subject against a cutoff, and track school works (assignments, quizzes, and exams) with reminders before they are due.

The application is built as a single codebase that runs on Mobile (Android/iOS), Web browsers, and Desktop (Windows/macOS), all backed by a RESTful API running on a local development server (localhost). The target audience is secondary and tertiary students who need a simple, fast, and reliable way to stay on top of their academic responsibilities.

1.2 Core Objectives
• Develop a unified cross-platform client supporting Mobile (iOS/Android), Web browsers, and Desktop environments (Windows/macOS).
• Build a functional RESTful API backend running on a local development server (localhost).
• Implement local data persistence and central management across all supported frontend platforms through a single authenticated account.

2. System Architecture & Tech Stack

2.1 Frontend Platforms
• Cross-Platform Framework: Flutter (Dart) — one codebase targeting all platforms
• Mobile Support: Android & iOS builds. Android is verifiable on the development machine; an iOS build requires macOS/Xcode and is included as a supported target.
• Web Support: Chrome / Edge / Firefox / Safari via Flutter Web.
• Desktop Support: Windows build (verifiable on the development machine); macOS build is a supported target requiring a Mac.
• Key frontend packages: http/dio (API client), provider (state management), flutter_secure_storage (JWT storage), flutter_local_notifications (reminders), table_calendar (weekly/daily schedule views).

2.2 Backend & Data Storage
• Development Environment: Node.js 22 LTS or newer on Windows (localhost server)
• Framework / Language: Node.js + Express (JavaScript)
• Database Management System: SQLite (file-based, server-side) accessed through better-sqlite3
• Authentication Method: JWT (JSON Web Tokens) with bcrypt password hashing
• Supporting libraries: jsonwebtoken, bcrypt, zod (input validation), cors, dotenv

3.2 Out of Scope
The following are explicitly excluded from this iteration and listed as future work:
• Real-time chat or messaging between users.
• Image / photo uploads (e.g., assignment attachments).
• Shared or multi-user class groups (attendance is per-student account only).
• Cloud push notifications and third-party integrations (Google Calendar, LMS).
• Payment, marketplace, or social features.
• Offline-first synchronization and conflict resolution.
